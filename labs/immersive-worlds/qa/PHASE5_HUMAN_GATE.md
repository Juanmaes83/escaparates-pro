## 6. Change Summary

### Escaparates Pro (Phase 2)
- New standalone website module: `living-art-pro`
- Complete Three.js pipeline with 9 semantic controls and 3 view modes
- Drag-drop image support with procedural fallback
- Dark editor UI matching EP visual language
- Bridge registration in `js/website-modules-ui.js`

### Museum (Phase 3)
- New LivingArtGuest nested runtime class following BreezeGuest contract
- Full pipeline: direction field, Poisson seeds, Bezier strokes
  (InstancedBufferGeometry), impasto composite, GPGPU boids, boid marks
- Registered in NestedRoomController alongside Breeze
- New space in world JSON with anchors, entity, and bidirectional portals

### Cross-Product (Phase 4)
- Six capabilities shared cleanly between both products
- No premature framework — capabilities are pure data transforms
- Each product has its own rendering adapter

## 7. Known Limitations

- Museum guest uses procedural artwork only (no user image upload yet)
- Impasto composite is static (rendered once at activate, no animated lighting)
- Boid marks faint in living-only mode against dark background
- SwiftShader CI rendering differs slightly from real GPU
- gradient-map capability imported but not actively used in either adapter yet
- No persistence — artwork state is ephemeral per session
- EP module inlines capabilities (no ESM import) due to r0.128.0 Three.js constraint
